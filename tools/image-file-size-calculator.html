Image File Size Calculator (Uncompressed)

Estimate the raw data size of an image before compression: width × height × bits per pixel. Useful for memory planning, RAW/TIFF estimates and image-sequence budgets.

Why real PNG and JPEG files are smaller

This tool calculates the raw pixel data: width × height × bits per pixel ÷ 8. PNG applies lossless compression and JPEG applies lossy compression, so their file sizes depend on image content and quality settings. A 24-megapixel RGB image contains about 72 MB of raw data, but a typical high-quality JPEG of the same image is 5–15 MB.

When to use this calculator

  • Planning memory requirements for textures, frames or image caches.
  • Estimating the size of uncompressed formats such as TIFF or BMP.
  • Budgeting storage or upload time for a batch of images.
  • Understanding why a compressed JPEG is much smaller than the raw pixel data.

Worked examples

  • 6000 × 4000 px, 24-bit RGB: 72,000,000 bytes - about 72 MB (68.7 MiB) uncompressed.
  • 6000 × 4000 px, 48-bit RGB: 144 MB uncompressed, as used by high-bit-depth TIFF files.
  • 1920 × 1080 px, 8-bit grayscale, 100 frames: about 207 MB in total.
  • 1024 × 1024 px, 32-bit RGBA: 4 MB per texture, which matters when a game loads hundreds of them.

Why compressed files behave differently

PNG uses lossless compression and typically shrinks images by 20–70%, depending on how much detail and noise they contain. JPEG is lossy and can reduce a photo to 5–15% of its raw size while still looking good at normal viewing distance. Flat graphics with large areas of solid colour compress far better than photographs with fine texture. This is why there is no reliable multiplier that converts raw bytes into a guaranteed JPEG or PNG file size.

Bits, bytes and channels

Bit depth describes how much data each pixel carries. 8-bit grayscale uses one byte per pixel; 24-bit RGB uses three bytes (red, green and blue); 32-bit RGBA adds an alpha channel; 48-bit RGB doubles the per-channel precision to 16 bits. File size scales linearly with bit depth: doubling the bits doubles the data.

Common mistakes

  • Expecting the calculator to predict JPEG size exactly - only the uncompressed baseline can be exact.
  • Confusing bits and bytes, which is an eight-fold error.
  • Forgetting the alpha channel when planning texture memory.
  • Believing that changing the DPI metadata alters the file size - it does not.

Frequently asked questions

How big is an uncompressed 6000 × 4000 RGB image?

6000 × 4000 × 24 bits ÷ 8 = 72,000,000 bytes, about 68.7 MiB (72 MB in decimal). This equals the size of an uncompressed TIFF or BMP before metadata.

Can you predict the JPEG or PNG file size exactly?

No. JPEG size depends on compression quality and image detail; PNG size depends on colour complexity. Treat any "average" multiplier as a rough guide only. This tool gives the exact uncompressed baseline instead.

Is this the same as the file size my camera produces?

Not usually. Cameras store compressed JPEGs or proprietary RAW formats that use their own compression and metadata, so the file on your card is smaller than the raw pixel data.
